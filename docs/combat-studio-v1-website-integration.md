# Combat Studio V1 website integration — real-data delivery contract

## This milestone
- Loads the nine generated V1 JSON datasets through a standalone consumer adapter.
- Requires `combat-studio-v1-bundle-manifest.json` by default and verifies each file's SHA-256 before parsing it.
- Rejects missing files, missing hashes, mismatched hashes, and a manifest marked `blocked`.
- Checks array/object shape and identity integrity, while retaining unknown values as unknown.
- Keeps this integration separate from the Trading Terminal, GE price API, Discord integration, Cloudflare routing, and existing account/loadout behavior.

## Data delivery contract
Serve one immutable, versioned bundle directory containing these ten files together:

- `combat-studio-v1-bundle-manifest.json`
- `items.json`
- `equipment-stats.json`
- `weapons.json`
- `item-requirements.json`
- `item-combat-profiles.json`
- `monsters-combat.json`
- `quests.json`
- `quest-relationships.json`
- `item-relationships.json`

The manifest is generated by `osrshub-game-data/scripts/build_combat_studio_v1_bundle_manifest.py`. It contains a SHA-256 digest per filename under `datasets[filename].sha256`. The browser loader checks the downloaded bytes against those digests before exposing parsed records. Keep the manifest and data files from the same database commit; never mix files from different runs.

The website adapter defaults to `/data/combat-studio-v1/`. A caller may pass a different `baseUrl` for a versioned static origin. For local fixture tests only, `verifyHashes: false` bypasses the manifest requirement; production callers should not disable it.

## Publishing guardrails
The database CI currently uploads its generated `dist/*.json` as a temporary Actions artifact. That artifact is not a permanent production URL and expires. Do not point the live website at a workflow-artifact download URL. Before production data is switched on, publish a stable, versioned bundle location and review:
1. Manifest status, file hashes, record counts, empty datasets, and source/provenance metadata.
2. Dataset size and client download cost; do not ship an oversized bundle to every visitor without measuring it.
3. Licensing and attribution requirements of the source data.
4. CORS and cache policy if the bundle is hosted on a separate origin.
5. A real-bundle smoke test in website CI, including the exact published manifest.

A structurally valid bundle is not proof of OSRS factual correctness, formula accuracy, account eligibility, or quest unlock coverage. An empty or review-required dataset must remain visible as a limitation rather than being treated as complete.

## Price and feature boundary
The game database is the source for game facts and item identities. Current GE prices continue to come from the existing separate price API and should be joined by item ID only where Combat Studio needs cost-aware recommendations. This change must not modify Trading Terminal logic or price fetching.

## Verification
```bash
npm test
npm run build
```

This milestone hardens data delivery and integrity checks. It does not yet activate the Combat Studio UI or claim that the production bundle has been published. The next acceptance step is to publish a stable immutable bundle, run the adapter against that real bundle, and then connect it to a dedicated Combat Studio screen with explicit loading/error/readiness states.
